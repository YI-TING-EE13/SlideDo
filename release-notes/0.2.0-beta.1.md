# SlideDo 0.2.0-beta.1

Release type: Beta readiness build.

## Highlights

- Android app flow includes Home, Mode Select, onboarding, guided practice,
  compact gameplay controls, Settings, Records, Results, and solver-assisted
  record protection.
- Desktop app now has comparable Home, Records, Preferences, Results, How to
  Play, Practice Tutorial, and Assist hint surfaces.
- Save files include release-readiness metadata for updated time, board size,
  move count, elapsed time, and active/solved state.
- Android Home shows Continue metadata so saved games expose board size, move
  count, elapsed time, active/solved state, and save freshness before resume.
- Desktop saves and records are stored in the user-data directory instead of
  the project root.
- Release scripts can build a signed Android release APK/AAB and a desktop ZIP
  package from the shared version metadata.
- Android Home, Game, Practice Tutorial, Mode Select, Records, Settings, and
  Results construction are split out of `MainActivity`, and connected
  instrumentation launch/scroll helpers are hardened for slow emulator runs.
- Android now includes adaptive and round launcher icon resources plus a Play
  Store readiness draft covering listing copy, privacy policy text, Data Safety
  answers, screenshot guidance, and the pre-launch device matrix.

## Verification

- Run `verify.bat` for shared tests, desktop compile, Javadocs, Android debug
  build, instrumentation APK assembly, and lint.
- Run `verify-release.bat` for signed Android release artifacts and the desktop
  package.
- Run `verify-connected.bat` with an emulator or device before public testing.
  Restart the emulator and rerun if the Android system process crashes during
  instrumentation; app regressions should reproduce on a healthy run.

## Known Limits

- Final feature graphic, reviewed store screenshots, published privacy policy
  URL, crash reporting decision, and broad device-size screenshot coverage are
  still planned.
- The desktop package is a ZIP plus optional `jpackage` app-image, not a signed
  installer.
- Screenshot smoke coverage is currently a repeatable capture workflow rather
  than a full pixel-diff gate.
