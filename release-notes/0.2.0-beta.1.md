# SlideDo 0.2.0-beta.1

Release type: Beta readiness build.

## Highlights

- Android app flow includes Home, Mode Select, onboarding, guided practice,
  compact gameplay controls, Settings, Records, Results, and solver-assisted
  record protection.
- Desktop app now has comparable Home, Records, Preferences, Results, How to
  Play, Practice Tutorial, and Assist hint surfaces.
- Records screens now explain that only player solves count, fewer moves rank
  first, ties use faster time, and assisted completions do not replace records.
- Save files include updated time, board size, difficulty, current and initial
  grids, move count, elapsed time, active/solved state, completed actions, and
  Redo actions. Legacy saves without action histories remain loadable.
- Android Home shows Continue metadata so saved games expose board size, move
  count, elapsed time, active/solved state, and save freshness before resume.
- Android Mode Select shows difficulty labels, expected session length,
  first-puzzle guidance, and local best records before a new game starts.
- Desktop saves and records are stored in the user-data directory instead of
  the project root.
- Release scripts can build a signed Android release APK/AAB and a desktop ZIP
  package from the shared version metadata.
- Android Home, Game, Practice Tutorial, Mode Select, Records, Settings, and
  Results construction are split out of `MainActivity`, and connected
  instrumentation launch/scroll helpers are hardened for slow emulator runs.
- Personal Play 2.0 adds offline backup/restore, Daily Calendar history replay,
  Favorite Puzzles, personal trends and weekly goals, Continuous Challenge,
  Move History/Redo, and adaptive accessibility reinforcement.
- The latest connected Android acceptance passed all 108 tests on both Pixel_7
  and `small_phone`, with no failures or skips.
- Android now includes adaptive and round launcher icon resources plus a Play
  Store readiness draft covering listing copy, privacy policy text, Data Safety
  answers, screenshot guidance, and the pre-launch device matrix.
- The Play Store readiness workflow now verifies the version-controlled feature
  graphic source, exports the 1024x500 PNG upload artifact, and checks store
  asset notes.
- Screenshot smoke capture now verifies the expected PNG set and writes a
  manifest for manual store screenshot review.
- A Windows GitHub Actions workflow now runs the same no-device CI gate as local
  development and uploads verification release artifacts.
- CI verifies the AGP 8.13.2, Gradle 8.14.5, JDK 17, SDK 36, and build-tools
  36.0.0 contract; workflow actions and the Gradle distribution are
  integrity-pinned, and Android lint treats warnings as errors.
- Release verification writes a SHA-256 artifact manifest for Android,
  desktop, store asset, and release-note handoff files.
- The current Android build keeps gameplay data on the device and contains no
  analytics, crash reporting, telemetry, ads SDKs, accounts, cloud save, or
  third-party tracking. Public distribution remains deferred.
- Desktop public beta readiness now has a dedicated handoff document and local
  package check, and release verification runs that check alongside Android Play
  Store readiness.
- Desktop ZIP packages now include a tester-ready README with runtime
  requirements, smoke-test prompts, save-location notes, and known limits.
- Android Play Store readiness now includes screenshot review, accessibility
  review, and pre-launch evidence worksheets for manual store handoff.
- Screenshot smoke manifests now include screenshot purpose labels and manual
  review checklist placeholders.

## Verification

- Run `verify.bat` for shared tests, desktop compile, Javadocs, Android debug
  build, instrumentation APK assembly, and lint.
- Run `verify-release.bat` for signed Android release artifacts and the desktop
  package. It also writes the release artifact manifest and runs the Android
  Play Store readiness file check.
- Run `ci.bat` to verify the pinned toolchain contract, local build/tests/docs,
  and release readiness in the same order used by GitHub Actions.
- Run `verify-connected.bat` with an emulator or device before public testing.
  Restart the emulator and rerun if the Android system process crashes during
  instrumentation; app regressions should reproduce on a healthy run.

## Known Limits

- Reviewed feature graphic upload file, reviewed store screenshots, published
  privacy policy URL, signed desktop installer decision, and broad device-size
  screenshot coverage are still planned.
- The desktop package is a ZIP plus optional `jpackage` app-image, not a signed
  installer.
- Screenshot smoke validates captured PNG readability and dimensions, but is
  not a full pixel-diff gate.
